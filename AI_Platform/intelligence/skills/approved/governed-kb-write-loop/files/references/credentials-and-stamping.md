# 凭据卫生与戳记（写面）

两条今天各自造成过一次真实故障的规则。

## 规则 1：产物里绝不戳凭据

**写面把 `created_by` 写成调用方身份时，必须记身份名，不能记令牌值。**

情况：写面适配器从 `INTELLIGENCE_TOKEN` 取到解析后的令牌并把它当成身份用，于是每条产物的 `created_by` 变成了一串明文令牌。产物树在版本控制内 → 一次 `git add -A` 就把凭据推进公开仓库。

做法：写出任何身份字段前，先做一次「令牌 → 身份名」反查；反查实现要**自包含在写面模块内**（跨目录 import 在这里静默失败过一次，把整个写面变成 `name '_identity_name' is not defined`，而它看起来只是「写入没返回内容」）。

验证方式：真写一条自检产物，读回 `created_by`，确认它等于身份名而不是长随机串。

## 规则 2：轮换令牌必须照登记表格式写

登记表（`identity_tokens.json`）每条形如 `"sha256:<64hex>"`，且顶部有 `scheme` 字段。

**加哈希时先读一条原有条目的实际形状，再照写。** 只写裸 `<64hex>` 会被一律判为未知令牌 → 新令牌静默 403，而旧令牌也已被覆盖，等于把自己锁在门外。

轮换的完整步骤：

1. 备份明文文件与登记表（`.bak`，权限 600）——这是唯一的回滚路径。
2. 生成新令牌，同时写两处：明文文件（客户端解析用）+ 登记表（网关比对用，**照格式**）。
3. 重启网关（哈希在启动时载入）。
4. 四路验证：新令牌读 = 200；旧令牌读 = 403；对不存在的 id 做写操作 = 404（说明写权限在，403 则没有）；只读面验收套件全绿。

## 规则 3：产物树里的凭据痕迹要能被搜出来

泄漏面核查不能只看代码：`grep -rl <值> <产物树>` + `git grep -l <值> $(git rev-list --all)`（历史命中必须为 0）+ 确认候选目录的 git 状态。发现痕迹后：走网关撤回（留痕），再抹除文件里的值，最后复搜一遍确认归零。
