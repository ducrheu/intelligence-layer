# 交付前检查表（植入段）

## A. 事实与边界

- [ ] 剧情段（开场/对话/结尾）与客户原稿**逐字一致**（用 diff 核对，不靠肉眼）
- [ ] 植入段里没有我们编的数字；所有数值位置是**内联括号**
- [ ] 括号写在正文里，不是只丢一句在段尾
- [ ] 括号格式统一：`（填时长）`/`（填百分比）`/`（填数值）`，段尾补一句"（括号处按当天实测填写）"
- [ ] 出现的每个品牌功能，都能在甲方材料里找到出处
- [ ] 参考样稿只借颗粒度，没有整句照抄（抽查 5 句）

## B. 结构

- [ ] 植入段拆成 3-5 镜，每镜有：景别 / 画面 / 口播 / 花字 / 秒
- [ ] 每一句都是"指标 → 它怎么分析 → 所以我怎么做"
- [ ] 深挖场景只有**一个**，其余指标各带一句
- [ ] 深挖场景里有"我跟着做之后的结果/好处"
- [ ] 功能名全部落在花字里，口播没有念功能清单
- [ ] 全片没有问答/聊天画面（除非品牌明确要 chat）
- [ ] 客户原稿里的互动台词（搭档捧场/疑问）保留

## C. 交付物

- [ ] xlsx 表名带 ①② 序号，**默认打开改写表**
- [ ] 有"植入段拆镜版"这张表
- [ ] 有"必提内容核对表"，逐条标落点
- [ ] 有"前后对比"表
- [ ] 有"时长分配"表，写明折算规则与字数
- [ ] 客户原稿备份一字未动
- [ ] 另出纯文本版（贴群用）与交付说明（验收/修改边界）

## D. 沟通

- [ ] 时长矛盾（表头 vs 分段相加）已主动指出，并给了方案 A/B
- [ ] 说明"含 2 次修改"与修改的颗粒度（按镜号）
- [ ] 说明数据留空的原因（数据还没测）

# 客户反馈归因模板

每轮反馈都按这四行记，避免第二次再犯：

| 客户原话 | 我的归类 | 根因 | 已固化的对策 |
|---|---|---|---|
| （逐字抄，不改写） | 事实错 / 结构错 / 越界 / 沟通不足 | 触发它的那一条规则 | 写进 SKILL 铁律或检查表 |

**越界**类反馈要格外记：客户说"这个不用你改"的地方，下次开工前先冻结。
