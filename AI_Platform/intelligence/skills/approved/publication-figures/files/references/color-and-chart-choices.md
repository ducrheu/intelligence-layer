# 配色与图型选择

配色不是审美问题，是**编码**问题：颜色要能把一个类别和另一个类别分开，并且在没有颜色时（黑白打印、
色盲读者）依然分得开。

## 一、默认色板：Okabe–Ito（Wong 2011）

`pf.colors(n)` 默认返回它，顺序即类别顺序 —— 前 N 个颜色两两可分。

| 序号 | 色值 | 名称 | 语义建议 |
|---|---|---|---|
| 1 | `#0072B2` | 蓝 | 基准 / 对照 / 本文方法 |
| 2 | `#E69F00` | 橙 | 第二类别（对比组） |
| 3 | `#009E73` | 绿 | 处理 / 改善 / 正向 |
| 4 | `#D55E00` | 朱红 | 强调 / 风险 / 退化（**只用一处**） |
| 5 | `#56B4E9` | 天蓝 | 背景类别 / 参考线 |
| 6 | `#CC79A7` | 紫红 | 第三/第四类别 |
| 7 | `#F0E442` | 黄 | 高亮（面积极小，慎用） |
| 8 | `#333333` | 深灰 | 注释文字、次要系列 |

语义色常量（多面板里保持一致）：`pf.C.BLUE` 对照、`pf.C.RED` 强调、`pf.C.GREEN` 处理改善、
`pf.C.ORANGE` 次级对比、`pf.C.PURPLE` 第三组、`pf.C.GREY` 非显著/背景。

`pf.setup(..., palette=...)` 可选三套：
- `okabe`（默认，色盲安全，推荐）
- `journal`（低饱和知性色，`#2166AC #B2182B #1B7837 #F1A340 #762A83 #666666`，接近 CNS 观感）
- `print`（灰度序列，明确要黑白出版/复印时用）

## 二、连续量的色图

| 数据类型 | 用什么 | 关键约束 |
|---|---|---|
| 有科学零点的有符号量（log2FC、z-score、相关系数） | `pf.C.DIV` / `pf.C.DIV_SAFE`，**必须 center=0** | 用 `pf.heatmap(..., center=0)`，否则正负被压扁 |
| 单向量（表达量、密度、偏差） | `pf.C.SEQ` / `pf.C.SEQ_RED` / `viridis` / `cividis` | 亮度单调；单色系更像论文 |
| 分类（≤7 类） | Okabe–Ito 顺序取色 | 超过 7 类就该分组或直接标注 |

**明令禁止**：`jet`、`rainbow`、`hsv`、`turbo`（亮度非单调，会凭空造出"边界"）、`tab10/tab20`、
`Set1/Set2/Set3/Paired`、seaborn 默认主题、Excel 默认色、纯红-绿单通道编码。
`critique.py` 的 C1/C2/C3 规则会自动拦这些。

## 三、图型选择表（按"你要证明什么"选，而不是按"哪个好看"）

| 你的结论 | 首选 | 不要用 | 备注 |
|---|---|---|---|
| 随时间/参数的趋势 | 折线 + 置信带（`pf.line_ci`） | 柱图串时间序列 | 标注转折点/半衰期，别让读者自己找 |
| 两组以上在若干条件下的高低 | 分组柱 + 误差棒 + 个体点（`pf.bars`） | 只有柱、没有散点和误差 | 柱子必须从 0 起；否则改用点图/棒棒糖 |
| 分布差异 | 小提琴/箱线 + 带状点 | 均值±SD 柱图 | 样本 <10 时点图优于箱线 |
| 相关性 | 散点 + 拟合 + `r/n/p`（`pf.scatter_fit`） | 只给相关系数矩阵 | 给出拟合线的类型与残差是否异方差 |
| 多变量相关 | 相关矩阵热图（发散色图居中） | 彩虹色热图 | 上/下三角可镂空，避免冗余 |
| 分类模型评估 | ROC + PR 双面板，报 AUC/AP | 只报"准确率" | 类别不平衡时必须给 PR |
| 消融/组件贡献 | 横向排序条 + 数值直接标注 | 3D 柱 | 从高到低排序，突出最优 |
| 流程/技术路线 | TikZ 或矢量绘图工具，嵌真实对象 | 纯文本框+箭头的通用流程图 | 框里放真实数据缩略（分布、前后散点）比放文字更有说服力 |
| 占比 | 排序条形或堆叠条 | 饼图/环形图（角度不可比） | 占比本身是结论时才用堆叠 |
| 多维概览 | 小倍数面板（small multiples） | 雷达图 | 雷达图面积随轴顺序变化，误导性强 |

## 四、多面板与中文场景的具体约定

- **一图一结论**：多面板是"证据链"，不是"贴图合集"。顺序按读者推理顺序排，而不是按你做完实验的顺序。
- **共享编码**：同一颜色/标记在整张图里只代表一件事；同一个变量跨面板必须共用色标（显式给 `vmin/vmax`）。
- **面板标签统一位置**（左上角，`pf.panel_labels(axes)`），字号大于正文标签（Nature 8pt 粗体）。
- **面板尺寸一致**，`wspace/hspace ≥ 0.3` 或让 `constrained_layout` 处理；不要贴着边。
- 中文报告里，轴标签写"相对误差 (%)"这种**量名+单位**；不要出现"误差率百分比(%)"这类冗余。

## 五、灰度与色盲自检（30 秒版）

1. 把 PNG 转灰度看一眼（`python -c "from PIL import Image; Image.open('f.png').convert('L').save('g.png')"`）：
   还能区分系列吗？
2. 线型/标记是否冗余编码（`-`、`--`、`-.`、`o`、`s`、`^`）？只靠颜色就说明不达标。
3. 颜色数是否 ≤7？超过就合并类别或直接标注。
4. 红色是否只出现在一处强调？大面积饱和红会显得"警报化"，印刷也不稳。
